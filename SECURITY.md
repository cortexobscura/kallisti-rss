# Security boundaries

Feed URLs, DNS answers, redirects, XML/HTML, raster bytes and incoming text are untrusted. Server origin and local filesystem paths are operator configuration. The server is trusted for identity/authorization and send acknowledgments; verified TLS remains mandatory. No insecure-TLS config, ambient HTTP proxy, private-feed allowlist, login bypass, SVG scripting or arbitrary gallery scraping exists.

Fetch connections validate all DNS answers then dial a validated literal address, preserving TLS hostname verification. HTTP redirects are limited and revalidated. Bounded headers, bodies, deadlines, XML depth, item count, text length, image byte/pixel dimensions and outbox capacity constrain work. Raster re-encoding strips original metadata. No feed-provided data determines a local filename, shell command, SQL fragment, log format or server auth header. SQL values are parameterized; the only dynamic UPDATE fragment is chosen from fixed command verbs.

Chat management requires server `verified=true`, present `authorId` and an explicit numeric allowlist plus configured channel. Incoming history/edits/self messages cannot execute commands. The WebSocket reader applies the same authorization before queueing, so unauthorized chat users cannot fill the command queue or force a reconnect; overflow by allowlisted commands drops the excess with a warning. Per-subscription and per-channel ingest limits stop one feed from exhausting the shared outbox. Command mutation, replay record and reply queue are one SQLite transaction. The allowlist defaults empty. Missing/expired auth or changed bot identity fails closed. Exactly one password or token file is operator-managed. Passwords go only to the fixed HTTPS login endpoint with redirects refused; resulting tokens are memory-only and reused across reconnects. Neither credential goes to feed/media origins. Discovery authenticates but performs no chat or database mutations.

The database lock is advisory and intended for one cooperative process on a local filesystem. Network filesystems, bypassing the lock externally, multiple replicas and manual writes while running are unsupported. Durable history grows without pruning; use filesystem quotas and monitoring. Serial image decoding is pixel-bounded but not process-isolated; keep Go/image dependencies patched. URLs can be publicly reachable but still undesirable: channel managers are trusted to choose appropriate feeds. File uploads become public-by-key on Kallisti; private content is out of scope.

No security claim depends solely on test coverage. See VERIFICATION.md for parser/SSRF/authorization/durability tests, security scanner versions and limitations. Gosec suppressions are narrow comments for operator-selected file paths and checked frame-size conversion; no rule is globally disabled. Synthetic demo credentials are intentionally non-secret and used only by its ephemeral loopback server.

For suspected issues, avoid sending tokens, private config, databases or URL query secrets in public reports. Reproduce using synthetic fixtures where possible. No private reporting channel is documented here; the repository owner should publish one. Repository publication and passing CI do not establish that this channel exists.


Delivery failures now use a closed set of local classifications derived from the pinned upstream error contract, only after exact nonce matching. Mismatched-channel/uncorrelated/unknown errors cannot bypass global failure handling. Error strings are converted to controlled labels within a 1024-byte encoded bound and discarded; echo text, credentials and arbitrary server text are never logged. Persistent retry metadata holds only job IDs, attempt counts/times and controlled labels. Quarantine is a per-channel ordering barrier, not an automatic discard. Operator reconciliation remains required for uncertain old work.
